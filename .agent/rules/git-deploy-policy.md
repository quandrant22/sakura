# Правило деплоя и синхронизации кода (Git Deploy Policy)

Это постоянное правило обязательно для всех агентов, работающих с проектом «Сакура».

---

## ⛔ КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО

- **Прямой деплой на VPS через `scp`, `sftp`, `rsync` или ручное копирование/создание файлов в обход Git.**
- Оставлять на VPS незакоммиченные, изменённые или рассинхронизированные файлы (`git status` на VPS всегда должен оставаться чистым).
- Пушить код без предварительного прогона релевантных локальных тестов.

---

## ✅ ЕДИНСТВЕННЫЙ РАЗРЕШЁННЫЙ СПОСОБ ДЕПЛОЯ НА VPS

Любое изменение, затрагивающее серверную часть (`modules/`, `sakura_core/`, `adapters/`, `capabilities/`, `config.py`, `main.py` и т.д.), обязано проходить следующий 4-шаговый цикл:

### Шаг 1. Локальная верификация тестами
Перед коммитом запусти локально все затронутые тесты:
```bash
pytest desktop/tests/ tests/
```
Убедись, что все тесты проходят без ошибок и регрессий.

### Шаг 2. Осмысленный Git Commit
Закоммить изменения локально. История коммитов репозитория является хроникой эволюции Сакуры.
- Формат сообщений: Conventional Commits (`feat(...)`, `fix(...)`, `refactor(...)`, `docs(...)`).
- В теле коммита кратко опиши: что изменилось, зачем, какие модули затронуты.
```bash
git add <нужные_файлы>
git commit -m "feat(module): понятное описание изменений"
```

### Шаг 3. Git Push в текущую рабочую ветку
Отправь коммиты в удалённый репозиторий:
```bash
git push origin <текущая_ветка>
```

### Шаг 4. Подключение к VPS, Pull и перезапуск сервиса
Подключись по SSH к VPS (`root@193.23.201.214` или хост из ssh-конфига):
1. Проверь чистоту рабочего дерева:
   ```bash
   ssh root@193.23.201.214 "cd /opt/sakura && git status"
   ```
2. Подтяни свежие коммиты:
   ```bash
   ssh root@193.23.201.214 "cd /opt/sakura && git pull origin <текущая_ветка>"
   ```
3. Проверь синтаксис/компиляцию Python:
   ```bash
   ssh root@193.23.201.214 "python3 -m py_compile /opt/sakura/main.py"
   ```
4. Перезапусти сервис и проверь статус и свежие логи:
   ```bash
   ssh root@193.23.201.214 "systemctl restart sakura && systemctl status sakura --no-pager"
   ssh root@193.23.201.214 "journalctl -u sakura.service -n 25 --no-pager"
   ```
5. Убедись, что `git status` на VPS остаётся абсолютно чистым.
