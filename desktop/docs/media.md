# Медиа: встроенные плееры и диспетчер

Код: `desktop/core/media/` (ядро) и экран «Медиа» в `desktop/ui` (плееры живут в окне).

## Правило цели

Действие `music.*` / `youtube.*` из реестра (`sakura_core/capabilities.yaml`, executor: agent)
идёт **встроенному** плееру, если он активен — играет или стоит на паузе меньше 10 минут
(`router.BUILTIN_IDLE_S`). Иначе — **внешнему**, как в старом агенте: SMTC и приложение
Яндекс.Музыки для `music.*`, вкладка браузера через расширение для `youtube.*`.
Тест на каждое из 30 действий: `desktop/tests/test_media_router.py`.

## music.* (18)

| Действие | Встроенный музыкальный плеер | Внешний (как раньше) |
|---|---|---|
| `music.play_pause` | пауза/продолжить | SMTC play/pause |
| `music.next` / `music.prev` | следующий / предыдущий в очереди | SMTC next / prev |
| `music.seek_forward` / `music.seek_back` | ±10 с | медиаклавиши / расширение |
| `music.shuffle` | перемешивание очереди вкл/выкл | расширение / приложение |
| `music.repeat` | повтор: выкл → всё → один | расширение / приложение |
| `music.mute` | звук плеера вкл/выкл | медиаклавиша mute |
| `music.volume_up` / `music.volume_down` | громкость плеера ±N % (число из фразы или VOLUME_STEP) | громкость системы ±N % (`nudge_volume`) |
| `music.now_playing` | «Исполнитель — Название» из встроенного плеера | SMTC + обогащение через API |
| `music.like` | Яндекс-трек → «Мне нравится» в Яндексе; локальный → плейлист «Любимое» | API Яндекс.Музыки по текущему треку SMTC |
| `music.dislike` | следующий трек; Яндекс-трек → дизлайк в Яндексе | API Яндекс.Музыки |
| `music.liked_tracks` | играть «Любимое» (или «Мне нравится» Яндекса при MUSIC_YANDEX=1) | API Яндекс.Музыки |
| `music.playlists` | список плейлистов медиатеки (ответ текстом) | API Яндекс.Музыки |
| `music.history` | последние прослушанные (история медиатеки) | API Яндекс.Музыки |
| `music.wave` | «Моя волна» Яндекса во встроенном плеере (MUSIC_YANDEX=1) | приложение Яндекс.Музыки (deep link) |
| `music.podcasts` | — нет аналога, всегда внешний | расширение / браузер |

## Связь с сервером (сервер не меняется)

- Пока играет встроенная музыка, `ping`/`register` несут поле `current_track` в том же
  формате, что SMTC: `title, artist, album, status («играет»/«пауза»), position/duration «м:сс»,
  progress` — так работает контекст реестра `playing:music`.
- Пока играет встроенное видео, `active_window` = «<название> - YouTube — Sakura Player»
  (для YouTube) — контекст `window:youtube`.

## Звук (`audio_session.py`)

Приоритеты: речь > слушание > видео > музыка. Пока Сакура слушает или говорит, встроенные
плееры приглушаются до `PLAYER_DUCK_PCT` (30 %) за 150 мс и возвращаются за 600 мс;
играет видео — музыка приглушена. «Стоп» ставит встроенные плееры на паузу. Системные
звуки и внешние приложения не трогаются.

## Файлы и безопасность

`media_server.py` слушает только 127.0.0.1, требует токен в каждом запросе, проверяет Host
и отдаёт файлы только через медиатеку и только из выбранных папок (realpath + commonpath;
`..`, `%2e%2e`, чужие диски и симлинки наружу не проходят). Тесты: `test_media_server.py`.

## Яндекс.Музыка (опция)

`MUSIC_YANDEX=1` + `YANDEX_MUSIC_TOKEN` в `.env`. Библиотека `yandex-music` неофициальная
(MarshalX, LGPL-3.0, API получен обратной разработкой); в интерфейсе — пометка
«неофициальный доступ». Ошибки и блокировки — понятное сообщение и откат на внешний плеер.
Токен не логируется и не попадает в тексты ошибок (тест `test_yandex_errors_hide_token`).

## YouTube

См. [network.md](network.md). Реклама не обходится и не скрывается, поверх плеера ничего
не рисуется, во фрейм youtube.com скрипты не внедряются, потоки не скачиваются.
