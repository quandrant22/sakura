# Защищённый канал Сакуры: Noise против TLS 1.3 и ГОСТ-подхода

Задача канала — защитить связь между ПК (и другими устройствами владельца) и сервером Сакуры на собственном VPS:
конфиденциальность голосовых команд и ответов, целостность команд управления ПК, подлинность сервера и устройств,
отзыв одного устройства без затрагивания остальных. Домена у сервера нет, удостоверяющий центр не используется,
устройств — единицы, все принадлежат одному владельцу.

## Варианты

| | Noise (securechannel/1) | TLS 1.3 (wss://) | ГОСТ-подход (TLS 1.3 с ГОСТ-наборами) |
|---|---|---|---|
| Стандарт | Noise Protocol Framework, rev. 34 (Perrin, 2018) | RFC 8446 | RFC 9367 (информационный, независимая публикация CryptoPro, 2023; IETF не рекомендует) |
| Обмен ключами | X25519 (RFC 7748) | X25519 / ECDHE P-256 | ECDHE на кривых ГОСТ Р 34.10-2012 |
| Шифрование и целостность | ChaCha20-Poly1305 (RFC 8439) | AES-GCM или ChaCha20-Poly1305 | «Кузнечик» (ГОСТ Р 34.12-2015, RFC 7801) или «Магма» (ГОСТ Р 34.12-2015, RFC 8891) в режиме MGM |
| Хеш | BLAKE2s (RFC 7693) | SHA-256/384 | «Стрибог» (ГОСТ Р 34.11-2012, RFC 6986) |
| Подпись / аутентификация | статические ключи DH (без подписи) | сертификат X.509 + подпись | сертификат + подпись ГОСТ Р 34.10-2012 (RFC 7091) |
| Доверие к серверу | ключ из спаривания (QR, 8 слов) | УЦ или закрепление отпечатка | сертификат российского УЦ или закрепление |
| Нужен домен / сертификат | нет | да (или самоподписанный + закрепление) | да (ГОСТ-сертификат) |
| Аутентификация клиента | ключ устройства в рукопожатии | токен в приложении или клиентский сертификат | клиентский ГОСТ-сертификат |
| Отзыв одного устройства | удалить ключ из реестра | отзыв клиентского сертификата (CRL/OCSP) или смена токена | то же, что TLS |
| Объём кода | ~300 строк машины состояний поверх готовых примитивов | библиотека (OpenSSL) | специализированная библиотека или КриптоПро |
| Библиотеки (Python) | PyCA cryptography (Apache-2.0/BSD), noiseprotocol (MIT) | stdlib ssl + OpenSSL | нативные — КриптоПро CSP (коммерческая) или OpenSSL + gost-engine (Apache-2.0); на Python — gostcrypto (MIT, чистый Python), pygost (GPLv3 — копилефт) |

## Эксперимент с ГОСТ

Библиотека — `gostcrypto` 1.2.5 (лицензия MIT; проверено по PyPI). `pygost` не использовалась: GPLv3 (копилефт),
в продукт её включать нельзя. Эксперимент — в отдельном venv, в продукт ГОСТ-код не входит.
Шифрование 64 КиБ, один поток, тот же ПК:

| Алгоритм | Реализация | МиБ/с |
|---|---|---|
| ChaCha20-Poly1305 | PyCA cryptography (нативный код) | ≈ 3400 |
| «Кузнечик», CTR | gostcrypto (чистый Python) | 0.055 |
| «Магма», CTR | gostcrypto (чистый Python) | 0.046 |
| «Стрибог-256» | gostcrypto (чистый Python) | 0.23 |

Разница — не в алгоритмах, а в реализации: на Python нет нативной ГОСТ-реализации со свободной лицензией.
«Кузнечик» в нативном коде (gost-engine) работает со скоростью порядка AES без аппаратного ускорения. Скриншот
в 2 МиБ через чистый Python шифровался бы ~40 с — для канала Сакуры непригодно.

## Выводы: почему Noise

1. **Нет домена и УЦ — и не нужно.** Noise IK опирается на ключ сервера, который устройство получает при спаривании
   (QR или 8 слов в Telegram). TLS без домена требует самоподписанного сертификата и закрепления — по сути то же
   «доверие к ключу», но с лишним слоем X.509 и продлением сертификатов.
2. **Аутентификация устройств встроена.** В Noise IK клиент доказывает владение своим ключом в первом же сообщении;
   отзыв одного устройства — удаление ключа из реестра. В TLS это клиентские сертификаты (громоздко) или токен
   поверх канала (общий токен нельзя отозвать для одного устройства).
3. **Мало кода, проверенные примитивы.** Клиент — машина состояний Noise поверх PyCA cryptography; совместимость
   с noiseprotocol (сервер) проверена тестами. Никакой собственной криптографии.
4. **Производительность не хуже TLS 1.3** (BENCHMARKS.md): рукопожатие ≈ 2.5 мс у обоих, пропускная способность
   выше, памяти на соединение в ~4 раза меньше.
5. **Работает поверх того же WebSocket и порта** — без смены инфраструктуры; старые клиенты работают в режиме
   `optional`, пока все устройства не спарены.
6. **ГОСТ** обоснован, когда нужна сертифицированная криптография (госсистемы, требования ФСБ). Для личного
   ассистента это требование отсутствует, а цена высока: ГОСТ-сертификаты, коммерческий КриптоПро или сборка
   OpenSSL с gost-engine на всех устройствах, нет свободной быстрой реализации на Python. RFC 9367 —
   информационный документ, наборы не рекомендованы IETF.

**Чем платим за Noise:** нет экосистемы X.509 (ротация ключа сервера — собственным сообщением `secure_server_key`),
длина сообщений видна (как и в TLS; padding — предложение для securechannel/2), реализация сервера и клиента должна
строго следовать спецификации — поэтому тесты совместимости и стенд атак обязательны.
