# Стенд атак на канал Сакуры

Цель — показать на работающем коде, от чего защищает securechannel/1 (Noise IK поверх WebSocket) по сравнению
с прежним `ws://` с общим токеном, и где граница этой защиты. Модель угроз — `docs/security/THREAT_MODEL.md`
(ветка сервера), спецификация — `docs/security/PROTOCOL.md`.

## Как устроен стенд

Всё локально, без реального сервера и без сети за пределами `127.0.0.1`:

- **сервер** — учебный `desktop/tools/securelab/server.py`: режимы `off` / `optional` / `required`, сеанс IK,
  спаривание XXpsk3, реестр устройств, единое поведение при любой ошибке рукопожатия (молчание до дедлайна,
  затем 4408), лимиты рукопожатий с адреса;
- **клиент** — настоящий код Сакуры: `desktop/core/transport.py` и `desktop/core/securechannel/`;
- **злоумышленник** — прокси «в середине» (`desktop/tools/attacklab/run_lab.py`, класс `Proxy`): пересылает кадры
  в обе стороны, пишет дамп и может повторять, менять и переставлять кадры, резать бинарные кадры.

Запуск: `python -m desktop.tools.attacklab.run_lab` (≈ 20 с). Результаты с таблицами и дампами —
[lab/RESULTS.md](lab/RESULTS.md). Секретов в отчёте нет: токен стенда учебный (`lab-token`), ключи одноразовые.

## Итоги (ДО — ws:// с токеном, ПОСЛЕ — Noise)

| Атака | ДО (ws://) | ПОСЛЕ (noise) |
|---|---|---|
| Перехват | видны токен и текст команды («включи свет в спальне») | только шифртекст и длины кадров |
| Повтор кадра | сервер исполняет повтор | 4409, соединение разорвано |
| Подмена кадра (1 бит) | сервер исполняет изменённое | 4409 |
| Перестановка кадров | сервер исполняет в новом порядке | 4409 |
| Повтор записанного IK_INIT | — | сервер отвечает IK_RESP, но без эфемерного ключа клиента злоумышленник не выводит ключи сеанса; в IK_INIT только идентификация — ничего не исполняется |
| Подмена сервера | клиент отдаёт токен самозванцу | клиент знает ключ сервера из спаривания — рукопожатие с самозванцем не проходит, данные не уходят |
| Кража секрета | украденный токен работает; отозвать — только сменить общий токен у всех | украденный ключ работает до `/revoke`; после отзыва — 4408, остальные устройства не затронуты; ключ в DPAPI — нужен вход под пользователем |
| Понижение до ws | — | `optional`: клиент **откатывается** на ws (с пометкой «не защищено»); `noise-only`: отказ; сервер `required`: текст — 4412 |
| Анализ длин | длины видны | длины тоже видны (+26 байт к ws: тег 16, заголовки 2+8) |
| Флуд рукопожатий | — | из 40 параллельных с одного адреса: 10 — 4429 (лимит), 30 — 4408 строго в дедлайн |

## Выводы и что сделано

1. **Конфиденциальность и целостность** — да: перехват, повтор, подмена и перестановка блокируются
   (AEAD с последовательным nonce, без попыток восстановления).
2. **Подлинность сервера** — по ключу из спаривания, без УЦ и домена. Подмена сервера не проходит.
3. **Понижение в режиме `optional`.** Злоумышленник, который режет бинарные кадры, заставляет клиента уйти на ws.
   Это ожидаемое поведение режима совместимости, но опасное. Сделано: интерфейс показывает «Не защищено» с причиной,
   есть режим `noise-only`. **Рекомендация:** после спаривания всех устройств переключить клиентов на `noise-only`,
   а сервер — на `SECURE_CHANNEL=required`.
4. **Утечка длины.** Noise не скрывает длину сообщения: по длине кадра можно отличить короткую команду от длинной.
   Спецификация securechannel/1 padding не задаёт (изменение кадра — только новой версией протокола).
   **Предложение для securechannel/2:** дополнять `DATA` до корзин (например 256 Б, 1 КиБ, 4 КиБ, далее кратно 16 КиБ);
   цена — до ~2× трафика на коротких сообщениях.
5. **Отзыв.** Отзыв одного устройства не трогает остальные — в отличие от общего токена.
6. **Перебор и неотличимость.** Неизвестный ключ, отозванный ключ, битое сообщение и неверный PSK неразличимы
   по времени: ответ всегда в момент дедлайна. Лимиты рукопожатий срабатывают.

## Ограничения стенда

- Сервер учебный: проверяет клиент и протокол, но не реализацию сервера на VPS (её стенд — у серверного агента).
- Атаки на конечные точки (вредонос на ПК, кража DPAPI под пользователем) вне модели угроз канала.
- Атаки по времени исследованы грубо (дедлайн), без статистики по микросекундам.
