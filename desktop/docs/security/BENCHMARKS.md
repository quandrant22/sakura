# Измерения канала: ws, wss и noise

Дата: 2026-10-16 08:38. Python 3.11.9, websockets 17.2, 8 логических ядер, Windows 10.
Сценарий: `desktop/tools/bench/run_bench.py`, сырые данные — [lab/bench.json](lab/bench.json).

## Методика

- Сервер и клиент — на одной машине, `127.0.0.1`: меряется **стоимость протокола** (рукопожатие, шифрование,
  кадры, сжатие), а не задержка интернета. На реальном канале до VPS к каждой цифре добавляется RTT сети.
- Сервер — учебный `securelab` (тот же код кадров и Noise, что у клиента); wss — TLS 1.3 с самоподписанным
  сертификатом стенда (ECDSA P-256), клиент проверяет его по файлу.
- **Установление соединения** — от `connect` до получения ответа на первое сообщение приложения
  (TCP + WebSocket + TLS или Noise IK + `register`/ответ); 60 повторов, медиана, p95, стандартное отклонение.
- **Пропускная способность** — эхо «туда-обратно» сообщений 256 Б…1 МиБ (400…8 повторов), данные
  **несжимаемые** (случайный base64 — как скриншоты и аудио); МиБ/с полезной нагрузки в одну сторону,
  в скобках — медиана времени одного обмена и разброс.
- **CPU** — время процессора процесса (пользователь + система) на одно сообщение; клиент и сервер в одном
  процессе, поэтому цифра — сумма обеих сторон.
- **Память** — прирост выделенной Python-памяти (`tracemalloc`) на одно открытое соединение (50 соединений).
- Варианты `-nc` — без `permessage-deflate`. Сейчас Сакура ходит по ws **со сжатием** (по умолчанию websockets);
  noise всегда без сжатия (см. ниже).

## Выводы

1. **Рукопожатие Noise IK стоит столько же, сколько TLS 1.3** (≈ 2.5 мс на локальной машине) и примерно вдвое
   дороже голого ws. На канале до VPS это меньше одного сетевого RTT и незаметно: соединение живёт часами.
2. **Шифрование не бутылочное горлышко.** Noise без сжатия передаёт ~190 МиБ/с на больших сообщениях — не
   медленнее ws без сжатия и быстрее wss. ChaCha20-Poly1305 в PyCA cryptography — нативный код.
3. **Главная находка — сжатие.** На несжимаемых данных `permessage-deflate` режет ws и wss до ~25 МиБ/с и даёт
   ~40 мс CPU на мегабайт. Первая версия клиента Noise тоже шла со сжатием и показывала те же 25 МиБ/с;
   отключение сжатия для noise (DECISIONS №52) дало ×7. Сжатие до шифрования к тому же раскрывает содержимое
   через длину (класс атак CRIME/BREACH) — для зашифрованного канала его выключать обязательно.
4. **Память:** noise ≈ ws без сжатия (~160 КиБ на соединение), TLS заметно тяжелее (~680 КиБ) из-за контекста
   OpenSSL. Для одного-трёх устройств это неважно, для сервера с сотнями соединений — заметно.
5. Разброс небольшой; выбросы у ws со сжатием (σ больше медианы) — сборщик мусора и буферы zlib.

## Ограничения

- Одна машина, оба конца в одном процессе Python — абсолютные цифры не переносятся на VPS, относительные — да.
- Сервер учебный; реализация сервера на VPS (noiseprotocol) может отличаться по скорости.
- Не мерилась задержка через реальную сеть и через VPN — это отдельный эксперимент на живом сервере.
