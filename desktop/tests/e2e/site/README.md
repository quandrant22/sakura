# Стенд сквозного прогона агента браузера

Локальные страницы для живой проверки связки «сервер → ядро → расширение 3.2.0». Внешних запросов нет. Ответы хранятся в `sessionStorage` вкладки, поэтому переживают перезагрузку страницы и перезапуск ядра.

| Страница | Что проверяет |
|---|---|
| `form.html` | Анкета из 6 полей: текст, email, select, radio, checkbox, textarea. Первая отправка получает «серверную» ошибку email (`aria-invalid="true"` и текст «Отправьте форму ещё раз»), вторая принимается. Итог выводится в `#result-json`. |
| `quiz.html?page=1` | Вопросы 1–4: single, multi, text и single, у которого условие есть только на картинке (`q4.svg`, текста условия на странице нет). Кнопка «Далее». |
| `quiz.html?page=2` | Вопросы 5–7: match (select в строках), order (select номеров 1…3), order (список перетаскивания, HTML5 DnD). Кнопка «Завершить». |
| `quiz.html?page=2&captcha=1` | Через 1,5 с появляется `.g-recaptcha`. Отметка «Я не робот» убирает её; пока она на странице, «Завершить» не принимается. |
| `result.html` | Сверка с эталоном `answers.json`: по каждому вопросу «верно», «неверно» или «нет ответа», итог в `#result-json`. |

Цели задач (`goal`) и эталон лежат в `answers.json`. В цели `{base}` заменяется адресом стенда.

## Запуск стенда

```sh
python -m http.server 8790 --bind 127.0.0.1 --directory desktop/tests/e2e/site
```

Адрес стенда: `http://127.0.0.1:8790/`. Чтобы пройти тест заново, нажмите «Пройти заново» на странице результата или откройте новую вкладку (`sessionStorage` очищается).

## Тестовое ядро (отдельно от рабочего)

1. Создайте worktree ветки. Это отдельный каталог, рабочий не затрагивается:
   `git worktree add <tmp>/sakura-e2e feat/browser-agent`.
2. Подготовьте env-файл тестового сервера вне репозитория: `VPS_WS_URL` (адрес тестового инстанса) и учётные данные для него. Файл готовит владелец или серверный агент. В отчётах и журналах его содержимое не печатается.
3. Запустите ядро с переменными процесса. Рабочий `.env` и `%LOCALAPPDATA%\Sakura` при этом не используются:
   ```powershell
   $env:SAKURA_ENV_FILE  = "<tmp>\e2e.env"      # прод-конфиг не меняется
   $env:SAKURA_DATA_DIR  = "<tmp>\data"          # удалить после прогона
   $env:EXTENSION_PORTS  = "8768"                # порт, отличный от рабочего ядра
   $env:BROWSER_UPLOAD_DIR = ""
   <tmp>\sakura-e2e\desktop\.venv\Scripts\python.exe -m desktop.core
   ```
   Переменные процесса не перекрывают ключи из `SAKURA_ENV_FILE` (`load_dotenv(override=True)`), поэтому адрес сервера задаётся именно в этом файле.
4. Запустите Opera GX отдельным экземпляром с временным профилем и расширением из worktree. Профиль удаляется после прогона:
   ```powershell
   & "$env:LOCALAPPDATA\Programs\Opera GX\opera.exe" --user-data-dir="<tmp>\gx-profile" `
     --load-extension="<tmp>\sakura-e2e\desktop\extension" `
     --disable-features=DisableLoadExtensionCommandLineSwitch --no-first-run
   ```
   Расширение перебирает порты 8766–8769 и подключается к тестовому ядру (проверка `sakura_hello`).

## Сценарии

| № | Сценарий | Как |
|---|---|---|
| а | Анкета | Задача с целью `form.goal`. Ожидается `#result-json` = `form.expected` и `attempts: 2`. |
| б | Тест | Задача с целью `quiz.goal`. На `result.html` сверяются ответы с эталоном. |
| в | Перезапуск ядра | В середине теста (страница 2) остановить ядро и запустить его снова: задача продолжается с того же вопроса (`browser.do` с `resume`). |
| г | Капча | Цель `quiz.goal`, адрес `quiz.html?page=1&captcha=1`. На 2-й странице задача уходит в паузу; отметить «Я не робот» в окне агента и нажать «Готово» в баннере, после чего задача продолжается. |
| д | Стоп | В середине теста сказать «стоп задача»: задача отменяется, окно агента остаётся открытым. |

Сценарии а и б выполняются дважды: с `BROWSER_NAV_THINKING=minimal` и с пустым значением. Режим переключают на сервере.

## После прогона

Удалите временный профиль Opera, каталог `SAKURA_DATA_DIR`, env-файл и worktree (`git worktree remove`). Кадры на диск не сохраняются.

## Автоматическая проверка стенда

`desktop/tests/extension/stand.test.js` (vitest, jsdom) прогоняет `content.js` по страницам стенда с их настоящими скриптами. Проверяются виды вопросов, пары match/order, перетаскивание через обработчики `quiz.js`, появление и уход капчи, а также ошибка email при первой отправке анкеты.
