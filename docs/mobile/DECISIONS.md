# Решения Android-клиента (feat/mobile-android)

Неясности задачи решаются осторожным вариантом; здесь — что выбрано и почему.

| № | решение | почему |
|---|---|---|
| D1 | `androidx.core:core` 1.18.0 (не 1.19.1) и OkHttp 5.3.2 (не 5.5.1) | 1.19.x и `okhttp-android` 5.5.x требуют compileSdk 37 (`checkAarMetadata`), а задача фиксирует compileSdk 36 |
| D2 | Тестовые зависимости сверх списка: Robolectric, `androidx.test:core`, OkHttp `mockwebserver3`, `org.json:json` | задача требует JUnit/Robolectric-тестов и мока на MockWebServer; `org.json` — настоящая реализация для чистых JVM-тестов (в android.jar только заглушки) |
| D3 | `lifecycle-livedata` и `lifecycle-viewmodel` входят в «lifecycle» из списка зависимостей | состояние экранов без своих Rx/корутин |
| D4 | Kotlin stdlib приходит транзитивно (OkHttp 5, androidx); прямых Kotlin-зависимостей и плагинов нет | разрешено задачей 0.1 |
| D5 | Gradle: `-Xmx2g`, `workers.max=2`, idle 10 мин; тесты: heap 1536 МБ, одна форка, `forkEvery 100` (заменяет прежние 1 ГБ/SerialGC и D12) | Paparazzi с layoutlib не укладывается в 512 МБ; перед прогоном проверяется свободная commit-память ≥ 4 ГБ, после — `gradlew --stop` |
| D7 | Нормализация 8 слов — как на сервере (`securechannel/pairing.py`): разделитель всё, кроме `[a-zа-я]` после `lower()` и `ё→е` | PSK считает сервер; десктопный порт (`[^\w]\|[\d_]`) расходится на экзотических символах — берём эталон сервера |
| D8 | Счётчик rekey считает каждый отправленный кадр (и REKEY/PING/PONG), перед PING/PONG тоже проверяется rekey | так делает `securechannel/channel.py`; иначе транскрипты расходятся побайтно |
| D9 | Ручное спаривание (адрес + 8 слов) без `k`: подлинность сервера — по кадру PAIRED (PSK) и отпечатку, который показывается для сверки с Telegram | в ручном вводе ключа нет; §3.3 разрешает |
| D10 | Таймаут рукопожатия клиента 8 с | сервер молчит до 5 с и закрывает 4408 — ждём с запасом |
| D11 | Векторы cacophony скопированы в `app/src/test/resources/noise_vectors.json` (источник — `securechannel/vectors/`), транскрипты генерирует `tools/gen_sc_transcripts.py` из серверного пакета (`backend=lib`) | тесты мобилки не читают файлы вне `mobile/android` |
| D12 | Тестовые JVM: heap 512 МБ, SerialGC, одна форка | на машине сборки ~0,5 ГБ свободной commit-памяти |
| D13 | Outbox только в памяти процесса (не на диске) | TTL 120 с; тексты — приватные классы, на диск не пишем |
| D14 | `register`: `proto: 2`, `kind: "phone"`, `system_info: {stats: {...}}`, `input_idle_s`, `active_window: ""`; без `token` | контракт; аутентификация — ключ Noise |
| D15 | Нет `registered` за 5 с → сервер считается v1: запросы v2 сразу `unsupported`, реплики `voice_command` работают | как десктоп (PROTOCOL §1.2) |
| D16 | Связь живёт, пока открыто приложение; в фоне — только при «Всегда на связи» (foreground specialUse). При уходе в фон без него — `bye{reason:"exit"}` | приложение личное; без лишней батареи |
| D17 | Тип FGS microphone добавляется только по запросу из открытого приложения; отказ системы — остаёмся specialUse | Android 14+ запрещает microphone-FGS из фона |
| D18 | «Говорить» в уведомлении открывает приложение (`ACTION_LISTEN`) | доступ к микрофону — только при открытом приложении |
| D19 | Метаболы: размытый диск ≈ логиста с σ пресета, объединение 1 − Π(1 − aᵢ), альфа = clamp(A·mul + add) — те же числа, что feGaussianBlur + feColorMatrix десктопа; одна формула в AGSL и на CPU | на программном холсте (Paparazzi, виджет) AGSL недоступен — снимки показывают ту же форму |
| D20 | Paparazzi 2.0.0-alpha05.1 (1.3.x не поддерживает AGP 9); тесты на Java, без Kotlin-плагина | требование снимков + «без Kotlin» |
| D21 | Тема «Как в наброске» сохраняет тёмные карточки на белом фоне (как десктоп); акцентные токены общие | UI.md |
| D22 | Снимки ядра в Paparazzi идут через CPU-растр `CoreShading.raster` (холст layoutlib программный, AGSL на нём не исполняется; путь выбирает `SakuraCoreView` по `isHardwareAccelerated`). Растр — та же формула, что AGSL, и он же нужен приложению (статичный кадр виджета), поэтому живёт в main. AGSL-путь покрыт: JVM-тест согласованности uniform-ов (`AgslUniformsTest`) и instrumented-тест компиляции и отрисовки шейдера (`CoreShaderInstrumentedTest`, запуск — RUNBOOK) | первый снимок проверен глазами: метаболы и градиент верные, не пустые |
| D23 | Модель Vosk закреплена по SHA-256 `961d5ff9…99a46d4` (46 236 750 байт, скачана и посчитана 2026-10-27); хеш проверяется до распаковки, неверный — файл удаляется; распаковка с защитой от zip-slip | «скачивается по кнопке с проверкой SHA-256» |
| D24 | Кнопка гарнитуры обрабатывается, только пока приложение на экране (`onKeyDown` HEADSETHOOK / MEDIA_PLAY_PAUSE); своей MediaSession нет | активная MediaSession перехватила бы управление музыкой Мастера |
| D25 | Голосовой ответ на вопрос confirm уходит обычным `voice_command` (channel `voice`), но помечен как confirm-ответ — в outbox не попадает; кнопки «Да»/«Нет» шлют `channel:"text"` (контракт) | без связи «да» не должно сработать позже |
| D26 | «Думаю» снимается первым `reply`/`tts_chunk` или через 20 с | сервер может не прислать ничего (сбой) |
| D27 | Дослушивание: после хода, если `tts_end.listen`, `reply.kind=confirm` или текст на «?»; окно — время до начала речи (дальше ждём финал распознавания) | точнее «6 с на ответ» |
| D28 | Чат шлёт `chat_send` (с `client_msg_id`, ждёт `chat_ack`), поиск и удаление — `chat_search`/`chat_delete` (имена текущего сервера, `sakura_core/proto_chat.py`), а не `history_search`/`history_delete` из SERVER_FEATURES; сервер v1 — `voice_command` channel:"text" | так отвечает реальный сервер |
| D29 | Триггеры `phone.*` и список действий конструктора — `assets/phone_triggers.json` из `tools/gen_phone_triggers.py`; пока в `capabilities.yaml` нет `phone.*`, они берутся из `tools/phone_triggers.seed.yaml` (14 действий контракта). После выката сервера генератор сам перейдёт на реестр; seed удалить | требование задачи |
| D30 | Экраны — «binder» (разметка + render(state)) отдельно от Fragment/ViewModel: снимки Paparazzi рисуют те же классы на демо-данных без связи | снимки всех экранов |
| D31 | Состояния снимков: экраны с данными сервера (Диалог, Пульт, Сводка, Сценарии, Память, Профиль, Безопасность) — normal/empty/offline/error; локальные (Голос, Интерфейс, Разрешения, Ещё) — normal; Диагностика — normal и offline; конструктор — пустой, предпросмотр, ошибка | у локальных экранов нет загрузки с сервера |
| D32 | Тема «Как в наброске»: формы и списки — в чёрных карточках, текст на фоне окна — токен `sakuraOnBg` (чёрный в «наброске», ink в «ночи»); вторичные кнопки — на подложке panel2 | белый фон «наброска» делал ink невидимым (найдено на снимках) |
| D33 | Память: ViewModel привязан к фрагменту и не переживает закрытия экрана; на диск не пишется | «без кэша» |
| D34 | Вопрос `reply kind:"confirm"` — общий диалог «Да/Нет» в MainActivity поверх любой вкладки; ответ — `voice_command` «да»/«нет» channel:"text", не в outbox, с тактильным откликом | контракт |
| D35 | Тестовая JVM: `-Djdk.attach.allowAttachSelf=true -XX:+EnableDynamicAgentLoading` | ByteBuddy (Paparazzi) иначе подключается через внешний процесс, а порождение процессов на машине сборки ненадёжно |
| D6 | Predictive back: `android:enableOnBackInvokedCallback="true"`; edge-to-edge — `EdgeToEdge.enable` + отступы по insets | targetSdk 36 |
