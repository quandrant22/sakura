# Решения автономной задачи (сервер)

Правило: при неясности — самый осторожный вариант; запись здесь.

| № | решение | почему |
|---|---|---|
| S1 | Пакеты для тестов (noiseprotocol, hypothesis, pytest-cov, qrcode) ставились в `/tmp/sc-extra` через `pip --target`, **не** в боевой venv `/opt/sakura/venv` | боевое окружение не трогать; в бой — через `requirements*.txt` и шаг runbook |
| S2 | ProVerif и прочие системные пакеты **не ставились** | системные изменения на проде без владельца; модель IK написана, помечена «не запускалась» |
| S3 | `SECURE_CHANNEL` по умолчанию `off` | выкатка без изменения поведения; включение — шагом runbook (`optional`) |
| S4 | Ключи и реестр — `memory/secure/` (каталог 700, файлы 600), а не `memory/*.json` | не смешивать с существующими файлами памяти; отдельный `.gitignore` |
| S5 | Словарь спаривания — 256 своих русских слов (64 бита на 8 слов) вместо BIP39 | клиенту словарь не нужен (PSK из нормализованного текста); 64 бит достаточно при одноразовости, 10 мин и 5 попытках |
| S6 | Все отказы рукопожатия — молчание и 4408 ровно в дедлайн | неотличимость неизвестного/отозванного ключа (ТЗ) |
| S7 | `device_id` при Noise берётся из реестра, а права master — по-прежнему по `MASTER_DEVICES` | спаривание не должно само давать права master |
| S8 | Соединения с loopback/адреса сервера = secure только для приватных классов; аутентификация (токен/ключ) нужна всегда | ТЗ (клиенты через локальный xray) + защита от пользователей VPN (T5) |
| S9 | Приватные классы в proto-v2-rest без модуля политики считаются НЕ secure (отказ) | если rest выкатят раньше securechannel — приватное не откроется по ws:// |

## Несколько устройств (server/multidevice)

| № | решение | почему |
|---|---|---|
| M1 | Ветка server/integration = master + securechannel + proto-v2-rest + server-autonomy; конфликты (.gitignore, config.py, commands.py, telegram.py) — оставлены обе стороны | ветки независимы по смыслу |
| M2 | В requirements.txt `noiseprotocol` был склеен с комментарием и не ставился — вынесен на свою строку | без него securechannel на проде не поднимется |
| M3 | Активное устройство одно — `presence_sync.get_active_device()`; `device_manager.get_active_device()` делегирует, `update_device` поле active_device больше не пишет | два источника + «последний ping» → скачки при трёх ПК |
| M4 | Пороги переключения 5 с / 30 с в константах `SWITCH_NEW_IDLE_S`, `SWITCH_CUR_IDLE_S`; пауза `TRANSFER_COOLDOWN` убрана | пороги сами гасят дребезг, пауза задерживала бы голосовое переключение |
| M5 | Голос/текст = `voice_command` и `chat_send` от master-устройства | других путей ввода текста с ПК нет (tg_message — уведомление в Telegram) |
| M6 | Нет `input_idle_s` — прежняя оценка по БД, и только когда активного ещё нет; дальше его меняют голос/текст или клиент с `input_idle_s` | иначе старые клиенты скакали бы, как раньше |
| M7 | Треки: `state.device_tracks`; глобальный `_current_track` удалён; «лайк/дизлайк» берут трек устройства, приславшего команду | иначе треки ПК смешиваются |
| M8 | Трек старше 60 с не учитывается (и у активного) | агент перестаёт слать current_track, когда музыки нет, — запись иначе висела бы вечно «играет» |
| M9 | `secure_devices`: «защищённый» = как у приватных классов (Noise или локальный источник), но проверка в обработчике не зависит от `PRIVATE_REQUIRES_SECURE` | список устройств не должен открываться отключением флага |
| M10 | `fingerprint` — 16 hex отпечатка без пробелов; `revoked` — bool | первые 16 символов, ключи не отдаём |
| M11 | proto 1: mood_update только `{"is_arrival"/"is_departure": true}` без параметров настроения | «только с is_arrival/is_departure» |
| M12 | `MOOD_BROADCAST=off` гасит только отправку в `broadcast_mood`; обновление вектора настроения продолжается | настроение влияет на промпт |
| M13 | Любой `device_id` из ping заводится в devices.json под своим id; `KNOWN_DEVICES` доливаются в старый файл | на проде devices.json без mostech: раньше ping от него молча игнорировался |
| M14 | `parse_device_from_text` не менялся | исполнение команд не менять |
| M15 | Агент (`agent/`, `desktop/`) не тронут: `input_idle_s` клиенты начнут слать отдельно, до тех пор работает прежняя логика | ограничение задачи |

| M16 | `note_input` и `announce_presence_transfer` идут фоновой задачей `spawn(..., name="presence-input")`, ошибки — в лог | голосовой ход не ждёт присутствие; цена: активное устройство обновляется на доли секунды позже начала хода |
