# Расписание вуза (МУИВ)

Сакура знает пары Мастера: отвечает «какие сегодня пары / где у меня пара», напоминает перед
первой парой, сообщает об отменах и сменах аудитории, учитывает пару в контексте присутствия.
Код — `sakura_core/schedule/`, команды — `capabilities/schedule.py`, решения — R1–R9 в
`docs/DECISIONS.md`.

## Источник

Страница `https://www.muiv.ru/studentu/fakultet-it/raspisaniya/` — оболочка; данные отдаёт один
запрос (`/services/timetable/scripts.js` → `get_data`):

```
POST https://www.muiv.ru/services/timetable/ajax.php
el=groupnames  branch=gv  year=Курс 2  faculty=Информационных технологий
studyform=Очная  groupname=ИД 86.1/М1-25  edulevel=
```

Ответ — JSON из HTML-фрагментов; нужно поле `ttable`: `<h2>DD.MM.YYYY (день)</h2>` и таблица
из 6 колонок (время, группа, дисциплина, аудитория, вид занятия, преподаватель). Горизонт —
около двух недель вперёд; дни без пар не выводятся.

**Защита сайта.** Перед ответом сайт проверяет куки JS-проверки (`__jhash_`, `__js_p_`, …).
Без них вместо JSON приходит страница со скриптом, который считает хеш и ставит куку. Браузер
проходит её незаметно, сервер (httpx) — нет. Обходить проверку не будем (R2), поэтому два
источника:

| источник | как | когда работает |
|---|---|---|
| `push` | букмарклет в браузере Мастера делает тот же запрос и шлёт `ttable` на VPS | сразу |
| `direct` | VPS сам опрашивает `ajax.php` в часы `SCHEDULE_SYNC_HOURS` | только если вуз внесёт IP сервера в исключения |

`direct`, получив страницу проверки, ставит статус `blocked` и не повторяет попытку 24 часа.

## Поток данных

```
ttable ── push_server (/schedule/push) ─┐
       └─ fetch.fetch_direct ───────────┴─► sync.ingest ─► parse ─► store.merge ─► diff
                                                                          │            │
                       query (команды, контекст, сводка) ◄────────────────┘   notify (proactive)
```

- `parse.parse_ttable` — колонки по шапке, нормализация аудитории (`ауд.531` → `531`), времени
  и вида занятия; заглушка антибота → `ParseError` (не «пар нет»).
- `store` — `memory/muiv_schedule.json`: прошлые дни 30 суток, внутри горизонта новой выгрузки
  она авторитетна, сегодня — объединение, за горизонтом — не трогаем. История изменений ≤ 50.
- `diff` — `added`, `removed`, `moved`, `room_changed`, `time_changed`, `teacher_changed` в окне
  (завтра … конец новой выгрузки).
- `notify` — изменения в ближайшие 48 ч сразу; напоминание за `SCHEDULE_REMIND_BEFORE_MIN` до
  первой пары дня; раз в сутки — «расписание устарело». Ночь и тишина откладывают доставку.

## Команды

| id | фразы | ответ |
|---|---|---|
| `schedule.today` | «какие сегодня пары», «расписание на сегодня» | голос: «Сегодня 1 пара: в 18:40 …, ауд. 531.»; Telegram — списком с видом и преподавателем |
| `schedule.tomorrow` | «какие пары завтра» | так же |
| `schedule.week` | «расписание на неделю» | по дням |
| `schedule.next` | «где у меня пара», «какая аудитория», «когда следующая пара» | идущая или ближайшая |
| `schedule.refresh` | «обнови расписание» | `direct` — опрос; иначе подсказка про закладку |

## Установка

1. `.env` на VPS: `SCHEDULE_PUSH_TOKEN=<длинная случайная строка>` (например, `python -c "import secrets; print(secrets.token_urlsafe(32))"`).
   Группа — `MUIV_GROUP`, `MUIV_YEAR`, `MUIV_STUDYFORM` (по умолчанию ИД 86.1/М1-25, Курс 2, Очная).
2. Caddy: блок `handle /schedule/push` из `Caddyfile.example`, `caddy reload`.
3. Перезапуск Сакуры — в журнале `[schedule] приём push: 127.0.0.1:8771`.
4. Сборка закладки (на VPS, строку не сохранять в репозиторий):
   ```
   SCHEDULE_PUSH_URL=https://<домен>/schedule/push SCHEDULE_PUSH_TOKEN=… \
     python tools/schedule_bookmarklet/build.py
   ```
   В браузере: новая закладка «Сакура: расписание», в поле адреса — выведенная строка.
5. Открыть (или обновить) страницу расписания, нажать закладку → «Сакура: 5 занятий, без изменений».
   Кука проверки сайта со временем истекает: на давно открытой вкладке сайт отдаёт заглушку даже
   браузеру, и закладка скажет «обнови страницу и нажми ещё раз».
   Раз в неделю достаточно (горизонт сайта — две недели); устареет — Сакура напомнит.

Новый семестр или курс — поменять `MUIV_YEAR`/`MUIV_GROUP` в `.env` и пересобрать закладку.

## Прямой опрос (после ответа вуза)

Письмо в ИТ-отдел: просьба добавить IP VPS в исключения защиты для
`/services/timetable/ajax.php` (2–4 запроса в сутки) или дать официальную выгрузку. После
разрешения: `SCHEDULE_SOURCES=direct,push`. Проверка: «обнови расписание» → «Обновила
расписание: N занятий…»; при ответе «сайт не пускает сервер» исключение ещё не действует.
